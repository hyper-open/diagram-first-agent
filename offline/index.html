从架构总览开始 直接看 ReAct
这不是“组件清单”，而是一条演化路径。 每个阶段都只增加当前真正需要的组件；等新问题出现，再进入下一级。

怎么读：先图后文

1看主图

先看清这一级有哪些组件、请求怎么流动。

2读图注

用编号步骤把图上的箭头翻译成一句话。

3看时序

理解一次请求在组件之间如何往返。

4再看文字

只读问题、取舍和优化，代码收在折叠区。

八级演进：每一级只解决一个新矛盾

00 · OVERVIEW

架构总览

六层架构、控制面/数据面、三类网关的分工，以及一张八级演进表。

 01 · REACT

ReAct，最小可用 Agent

LLM + 本地工具 + 循环。理解“观察—思考—行动”为什么是 Agent 的心跳。

 02 · TOOL CALLING

工具调用与注册

用 JSON Schema 和 Tool Registry 替代脆弱的文本解析，建立错误契约。

 03 · MODEL GATEWAY

模型网关与路由

多模型接入、路由、回退、配额与成本：把模型访问收拢成一个内部服务。

 04 · TOOL GATEWAY

工具网关

跨团队工具的鉴权、限流、凭证托管、审计与协议适配，防止 Agent 变成超级账号。

 05 · RAG

RAG 与知识层

索引/查询两条流水线、权限感知检索、Agentic RAG，以及引用与冲突处理。

 06 · INTENT

意图识别与路由

FAQ、工作流、RAG、Agent、人工各走其路；用置信度和兜底控制误路由。

 07 · MULTI-AGENT

多 Agent 协作

主管/工人、分层、辩论；交接契约、共享状态，以及什么时候不该用。

 08 · PLATFORM

平台化与治理

计费流水线、安全边界、评测与可观测、控制面，以及最小可用平台清单。

先看总览：Agent 平台的六层（组件视角）

L6接入层API Gateway、身份、租户、限流、WAF
L5编排层意图路由、Agent Runtime、工作流、多 Agent、终止与预算
L4能力层Model Gateway、Tool Gateway、RAG、Memory
L3执行层沙箱、浏览器、代码解释器、Computer Use
L2数据层状态、向量库、对象存储、计费账本、审计
L1治理面可观测、评测、策略、配额、版本与发布

数据面负责“把这次请求做完”，控制面负责“所有请求按什么规则做”。平台化的核心，是把散落的规则收拢到控制面。

这六层是组件视角。想知道某个功能该由谁负责、出问题先查哪一层，看分层架构的七层职责模型——两套编号的对应关系在那一页末尾有换算表。

这本书怎么读

第一次接触 Agent

按「架构总览 → ReAct → 工具调用 → Mini Agent Lab 1–2」走，先跑通一个能调用工具的最小循环。

已经在做系统

重点看「模型网关 → 工具网关 → 平台化」，把鉴权、配额、计费、回退和审计补齐。

在做产品/平台

从「RAG → 意图识别 → 多 Agent → 平台化」切入，同时读评测与安全，先立指标和护栏。

你会得到什么

  • 一条能解释“为什么系统长成今天这样”的架构演进主线。
  • 每级架构的组件边界、请求时序、故障模式与优化手段。
  • 对网关、路由、RAG、意图识别、多 Agent、计费与安全的工程判断。
  • 一个不依赖框架的 Mini Agent 实现，以及可运行的评测 harness。
