阶段 5：RAG 与知识层

Agent 会调工具，但它仍然不知道公司内部的产品文档、昨天的价格、客户的合同。

一图看懂

flowchart LR Q["用户问题"] --> A["Agent"] A -->|"search_knowledge"| R["RAG 服务"] R --> A A --> L["LLM"] L --> O["回答 + 引用"] R --> T["Tool Gateway"]

一图看懂 · RAG 不是“把文档塞进 prompt”，而是一个可被 Agent 调用的知识服务

1索引

连接数据源、解析、切分、embedding、建索引。

2查询

改写问题、混合检索、权限过滤、重排。

3组装

片段 + 来源 + 时间 + 冲突提示。

4引用

每个关键结论可追溯到来源。

本章另有 4 张图：图 1 索引流水线，图 2 查询流水线，图 3 管线式与 Agentic 的取舍，图 4 权限过滤。

两条流水线

见图 1：

权限感知：最容易漏的一环

见图 4：

flowchart LR Q["查询"] --> F["tenant / user / ACL 过滤"] F --> C["只召回有权访问的片段"] C --> R["重排"] R --> S["引用只展示可访问来源"] X["全量召回后再过滤"] -.->|"错误做法"| C

图 4 · 权限过滤发生在召回阶段；索引里必须有可过滤的元数据

ACL 要在索引期写入元数据，查询时过滤，而不是取回结果再筛。删除、留存与跨境的要求见隐私与数据治理；召回质量怎么量化，见检索层。

它解决了什么，又制造了什么

解决了 同时制造了
知识过时 切分破坏语义，答案跨段丢失
私有数据不可见 相似度 ≠ 相关性，top-k 全是噪声
幻觉 / 无依据 多跳问题单次检索不够
无法追溯 来源冲突、旧文档未下线
上下文装不下 检索内容注入、权限泄露
权限差异 索引/重排/长上下文成本高

参考答案与自检

1. 写一张索引元数据表 要点：至少包含 doc_id / tenant / acl / source / updated_at / section_path / page。缺 acl 就无法在召回阶段过滤，缺 section_path 就无法给出可信引用。 自检：如果表里只有“内容 + 向量”，你的 RAG 只能做演示。

2. 五条路由（FAQ / 查单 / RAG / Agent / 人工） 要点：每条都要写出低置信兜底，且兜底不能是“再来一次”。例如 FAQ 低置信 → RAG；RAG 无命中 → Agent；Agent 涉及不可逆动作 → 人工。 参考设计见意图识别的置信度分叉；自检：五条路径里若没有“人工”，说明高风险出口缺失。

3. “无权限但语义相关”的检索用例 要点：测试要断言召回结果不含该文档（而不是“回答里不出现”）。后者仍然泄露了存在性。 自检：过滤发生在召回之后（如重排后再删）属于未通过——见检索层第七节“权限过滤：越早越好”。
