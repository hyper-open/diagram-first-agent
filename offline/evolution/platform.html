阶段 8：平台化与治理：计费、安全与评测

能跑不等于能运营。平台化要回答：谁在用、花了多少、安全吗、变好了吗。

一图看懂

flowchart TB U["客户端 / API"] --> AG["API Gateway"] AG --> OR["Intent Router<br/>Runtime / Workflow"] OR --> CAP["Model GW · Tool GW<br/>RAG · Memory"] CAP --> EX["模型 · 工具 · 知识库 · 沙箱"] OR --> OBS["Trace · Eval · Metering"] MG["控制面<br/>目录 · 注册 · 策略 · 配额"] -.-> OR MG -.-> CAP

一图看懂 · 平台参考架构：数据面负责执行，控制面负责规则

1谁在用

身份、租户、配额。

2花了多少

计量、计费、成本归因。

3安全吗

权限、注入、外泄、审计。

4变好了吗

评测、观测、灰度、回滚。

flowchart TB I["身份 / 租户"] --> P["策略引擎"] P --> C["能力令牌"] C --> T["Tool Gateway"] T --> S["沙箱"] S --> E["出口控制 / DLP"] E --> A["审计 / 告警"]

图 2 · 安全是一条链路：身份 → 策略 → 能力 → 执行 → 出口 → 审计

图 3 · 致命三要素：私有数据 + 不可信内容 + 对外通信，至少要切断一条

威胁 防线
直接/间接注入 数据标记、指令层级、出口控制、高风险审批
混淆代理 权限绑定真实用户，每次调用都授权
数据外泄 网络白名单、DLP、禁元数据地址
工具投毒 来源审查、版本锁定、隔离运行
记忆污染 来源/置信度、租户隔离、可删除
沙箱逃逸 容器/微虚拟机、非 root、只读根文件系统
违规内容 分级审核、流式拦截、拒答话术（见内容安全与审核）
隐私泄露 数据分级、日志脱敏、记忆可删（见隐私与数据治理）
合规缺失 备案、内容标识、审计留痕（见合规与法律）

五、成熟度与取舍

级别 特征 建议
L1 原型 单进程、本地工具、无计费 先验证任务价值
L2 团队 网关、基础观测、简单配额 多团队共用前补齐
L3 平台 控制面、计费、安全、评测、多租户 对外产品/规模化

每一个平台组件都应该对应一个真实、反复出现的问题。不要为了“平台感”提前建 L3。

最小可用平台清单

可复制模板

本章的清单有对应的结构化版本：preflight_checklist.json、usage_event.json、trace_step.json。全部模板见 examples/templates/README.md。

  • [ ] 统一身份与租户，所有调用可归因
  • [ ] 模型网关：路由、回退、配额、用量记录
  • [ ] 工具网关：注册、鉴权、限流、审计
  • [ ] 沙箱：代码/浏览器隔离，无宿主凭证
  • [ ] 策略引擎：高风险审批，默认拒绝
  • [ ] Trace：每步模型/工具/成本可查
  • [ ] 评测集 + 回归门禁
  • [ ] 计费/配额：至少能回答“谁花了多少”
  • [ ] 版本化与回滚：模型/提示/工具独立
  • [ ] 失败分类与告警：知道哪里坏了

参考答案与自检

1. 一次模型调用要记录哪些字段才能算清成本 要点：tenant / agent / model / input_tokens / cached_tokens / output_tokens / 工具调用次数 / 沙箱秒数 / idempotency_key。缺 cached_tokens 会把成本算高，缺 idempotency_key 会把重试重复计费（本章“五个坑”里的前两个）。 参考结构见本章“计费”一节的 usage event JSON。

2. 重试、缓存、异步任务如何避免重复计费 要点：账本不可变，用冲正记录；每一笔计量都带幂等键，由网关而不是调用方生成。 自检：如果“退款/调账”是直接改原记录，说明账本可被篡改，对账一定对不上。

3. 最小可用平台清单：只保留当前真正需要的组件 要点：按本章第五节的三级成熟度表打分——你是 L1 原型，就不要建 L3 的控制面。判断标准是“这个问题是否已经反复发生”，而不是“别人有没有”。 自检：清单里如果有组件说不出它对应哪个已发生的问题，就删掉它。
