# 运行时与沙箱：动作真正发生的地方

## 一图看懂

```mermaid
flowchart LR
  P["进程"] --> C["容器"] --> G["gVisor"] --> V["微虚拟机"]
```

<p class="diagram-caption"><strong>一图看懂</strong> · 隔离强度与成本递增；模型生成代码至少需要容器级隔离</p>


前面几层都在“决定做什么”。运行时层负责“真正做”。它决定了 Agent 的能力边界，也决定了**最坏情况下能造成多大破坏**。

一个反直觉的事实：**Agent 的安全事故，大多不是模型“变坏”，而是运行时给了它过大的权限。**

## 一、为什么需要沙箱

Agent 会执行模型生成的代码、命令、浏览器操作。这些输入：

- 可能是错的（模型幻觉）。
- 可能被注入（网页/文档/工具结果里的恶意指令）。
- 可能被用户恶意利用（越狱、提权）。

如果没有隔离，一次 `rm -rf /`、一次 `curl $SECRET`、一次 `pip install` 恶意包，就可能造成不可逆损失。

沙箱的目标不是“让 Agent 不犯错”，而是**让错误可控**：

- 限制能看到什么（文件、网络、密钥）。
- 限制能改什么（只读挂载、写白名单）。
- 限制能用多少（CPU、内存、时间、磁盘）。
- 限制能带走什么（网络出口、剪贴板、日志）。
- 出事能回溯（快照、审计、回滚）。

## 二、隔离级别：没有绝对安全，只有成本曲线

| 级别 | 机制 | 隔离强度 | 启动速度 | 适用 |
| --- | --- | --- | --- | --- |
| 同进程 | `exec`/`eval` | 极弱 | 即时 | 仅可信代码，教学演示 |
| 子进程 | fork/exec + 资源限制 | 弱 | 毫秒 | 本地只读工具 |
| 容器 | namespace + cgroup + seccomp | 中 | 百毫秒–秒 | 大多数代码执行 |
| gVisor | 用户态内核 | 中强 | 秒级 | 多租户代码执行 |
| 微虚拟机 | Firecracker 等 | 强 | 百毫秒–秒 | 不可信代码、多租户 |
| 独立 VM | 完整虚拟化 | 最强 | 秒–分钟 | 高风险/桌面操作 |
| WASM | 能力型沙箱 | 强（但生态受限） | 毫秒 | 插件、轻量计算 |

> 容器不是安全边界。共享内核意味着内核漏洞可能逃逸；对不可信代码，优先微虚拟机或 gVisor，并叠加 seccomp/AppArmor、只读根文件系统、无特权用户。

### 选择建议

- **内部工具、可信代码**：子进程 + 超时 + 工作目录隔离，够用。
- **多租户、模型生成代码**：容器 + 严格 seccomp/网络策略；高风险场景上微虚拟机。
- **Computer Use**：独立 VM/桌面会话，不碰宿主机。
- **浏览器**：独立 profile、禁用扩展、限制下载、代理出口。

## 三、资源限制：必须有的六条

```text
1. 墙钟超时（含工具内部阻塞）
2. CPU 时间上限
3. 内存上限（OOM 可杀）
4. 磁盘/输出大小上限
5. 进程/线程数上限
6. 网络出口白名单 + 带宽/请求数限制
```

没有超时的工具，是 Agent 系统里的定时炸弹。模型可能生成一个死循环，或者调用一个永不返回的 API。

### 输出也要限制

一个 `cat` 大文件、一次 `npm install` 日志、一个网页全文，都可能瞬间撑爆上下文。运行时应该：

- 截断 stdout/stderr（保留头尾，标注截断）。
- 把完整输出写到文件，返回路径 + 摘要。
- 限制单次工具返回的字节数。

## 四、文件系统：最小可见性

推荐布局：

```text
/workspace       读写，任务目录（挂载）
/workspace/.git  只读或受限（防止改写历史）
/input           只读，用户上传
/output          只写，产物
/tmp             临时，任务结束清理
```

原则：

- 默认只读，按需开放写。
- 不挂载宿主机 home、SSH key、云凭证。
- 不暴露 Docker socket（等于 root）。
- 路径规范化，阻止 `..` 穿越和符号链接逃逸。
- 任务结束销毁或快照，避免残留。

## 五、网络：默认拒绝

Agent 需要联网（查资料、装依赖），但网络是数据外泄的主要通道。

推荐：

```text
默认：无网络
按需：域名白名单 + 方法/端口限制
代理：所有流量经审计代理，记录域名与字节数
禁止：云元数据地址（169.254.169.254）、内网网段、控制面
```

尤其注意**云元数据服务**：如果沙箱能访问它，攻击者可能拿到实例凭证。

### 数据外泄的隐蔽通道

即使限制 HTTP，仍有：

- DNS 查询（把数据编码进子域名）。
- 时间侧信道。
- 图片加载/像素追踪。
- 剪贴板、打印、通知。

高安全场景需要更严格的出口控制，甚至离线执行 + 人工导出。

## 六、密钥：不要放进沙箱

最常见的错误：把 API Key、数据库密码作为环境变量注入沙箱。一旦模型能执行代码，它就能读环境变量、读文件、发网络请求。

更好的模式：

- **凭据不进沙箱**：由宿主代理调用外部 API，沙箱只拿短期、限权、限时的 token。
- **按需注入**：只在特定工具调用时注入，且绑定用户/租户/任务。
- **最小权限**：只读 token、单资源 scope、短 TTL。
- **可撤销**：任务结束立即失效。
- **审计**：记录谁在何时用哪个凭据做了什么。

## 七、Computer Use：把整个桌面当工具

Computer Use 让模型通过截图 + 鼠标/键盘操作软件。它的运行时通常是：

```text
独立桌面 VM
  ├─ 虚拟显示器（固定分辨率）
  ├─ 浏览器/应用
  ├─ 输入注入（鼠标/键盘）
  ├─ 截图/OCR
  └─ 无宿主机文件/网络直通
```

### 工程难点

| 难点 | 表现 | 缓解 |
| --- | --- | --- |
| 延迟高 | 每步截图 + 推理，秒级 | 降低截图频率、区域裁剪、并行 |
| 坐标脆弱 | 分辨率/缩放/弹窗导致点错 | 固定环境、先用可访问性树/选择器 |
| 状态不可见 | 不知道页面是否加载完 | 等待条件、截图差分、显式检查 |
| 验证困难 | 点完不知道成功没 | 读回状态、断言、人工确认 |
| 注入风险 | 页面内容诱导点击 | 高风险动作确认、域名白名单 |
| 成本高 | 每步都传截图 | 压缩、只在需要时看屏幕 |

> Computer Use 是“最后手段”。能用 API 就用 API，能用 DOM/选择器就用选择器，都不行才用坐标点击。

## 八、可复现性：出了事能重放

一个生产级运行时应该记录：

```json
{
  "task_id": "...",
  "image_digest": "sha256:...",
  "command": ["python", "fix.py"],
  "cwd": "/workspace",
  "env_keys": ["PATH", "LANG"],
  "stdin": null,
  "exit_code": 1,
  "stdout_sha256": "...",
  "stderr_sha256": "...",
  "duration_ms": 1240,
  "resource_usage": {"cpu_ms": 900, "max_rss_kb": 120000},
  "network": [{"host": "pypi.org", "bytes": 1200}],
  "artifacts": ["/output/patch.diff"]
}
```

可复现的关键：

- 镜像/依赖版本锁定（digest、lockfile）。
- 环境变量白名单。
- 随机种子（能固定的部分）。
- 输入快照。
- 输出与副作用记录。

## 九、一个安全的子进程执行器

```python
import os, resource, subprocess, tempfile
from pathlib import Path

def run_sandboxed(cmd: list[str], workspace: Path, timeout_s: int = 30,
                  max_mem_mb: int = 512) -> dict:
    env = {"PATH": "/usr/local/bin:/usr/bin:/bin", "LANG": "C.UTF-8"}

    def limits():
        resource.setrlimit(resource.RLIMIT_CPU, (timeout_s, timeout_s))
        resource.setrlimit(resource.RLIMIT_AS,
                           (max_mem_mb * 1024 * 1024,) * 2)
        resource.setrlimit(resource.RLIMIT_FSIZE, (10 * 1024 * 1024,) * 2)
        os.setsid()

    try:
        proc = subprocess.run(
            cmd,
            cwd=workspace,
            env=env,
            capture_output=True,
            text=True,
            timeout=timeout_s,
            preexec_fn=limits,
            shell=False,          # 禁止 shell 注入
        )
        return {
            "ok": proc.returncode == 0,
            "exit_code": proc.returncode,
            "stdout": truncate(proc.stdout, 20_000),
            "stderr": truncate(proc.stderr, 20_000),
        }
    except subprocess.TimeoutExpired:
        return {"ok": False, "error": "timeout", "retryable": True}
```

这段代码只是**最低限度**的本地隔离，不是安全沙箱。生产环境请用容器/微虚拟机，并叠加：

- 非 root 用户。
- 只读根文件系统。
- seccomp 白名单。
- 网络策略。
- 审计与告警。

## 十、审批：把不可逆动作交给人

不是所有动作都适合同一个权限级别：

| 级别 | 例子 | 策略 |
| --- | --- | --- |
| 只读 | 读文件、搜索 | 自动允许 |
| 低风险写 | 写工作区、生成草稿 | 自动 + 审计 |
| 中风险 | 提交代码、发内部消息 | 可配置审批 |
| 高风险 | 转账、删除生产数据、发外部邮件 | 强制人工确认 |
| 禁止 | 提权、访问密钥、修改审计 | 直接拒绝 |

审批界面要给出：**做什么、为什么、影响范围、可回滚吗、证据**。不要只弹一个“允许/拒绝”。

## 十一、运行时的度量

- 沙箱启动延迟、执行延迟 P50/P95。
- 超时率、OOM 率、被杀率。
- 网络拒绝次数（可能是攻击信号）。
- 资源利用率与成本。
- 逃逸/越权告警（应为 0）。
- 任务可复现率（同样输入能否得到同样环境）。

## 常见问题速查

| 症状 | 先查什么 | 可能修复 |
| --- | --- | --- |
| 命令偶尔卡死 | 是否有超时/进程组清理 | 墙钟超时 + kill 进程组 |
| 磁盘被写满 | 输出/临时文件限制 | 配额、清理、只读挂载 |
| 密钥泄露 | 是否注入环境变量 | 移出沙箱、短期 token |
| 能访问内网 | 网络策略 | 默认拒绝 + 白名单 + 禁元数据 |
| 同样任务结果不同 | 环境/依赖/数据漂移 | 镜像 digest + 快照 |
| 点错按钮 | 坐标/等待/分辨率 | 选择器优先、固定环境、断言 |
